# 교재(textbook) 규격 — 트랙 하나당 JSON 파일 하나: data/textbook/<track>.json

목표: "문제를 풀게 하는 앱"이 아니라 **차근차근 읽으며 전문가가 되는 과정**. 각 장(chapter)은 실제 업무 흐름의 한 단계이고, 신입이 그 단계를 맡았을 때 알아야 할 개념 → 실제 예 → 스스로 점검 순으로 쓴다. 독자는 온실가스관리기사 수준 또는 그 이하(Scope가 뭔지 모를 수 있음). 쉬운 말, "~다" 체, 전문용어는 처음 나올 때 한 줄 풀이.

```json
{
 "track": "lca",
 "title": "LCA 컨설턴트 과정",
 "intro": "2~3문장: 이 과정을 마치면 무엇을 할 수 있나",
 "chapters": [
  {
   "id": "lca-1",                       // courses.json의 chapter id와 같아야 함
   "title": "목표와 범위 정의",
   "workflow": "실무에서 이 단계가 언제, 누구와, 어떤 산출물로 끝나는지 2~3문장",
   "pages": [
    {
     "id": "lca-1-1",
     "title": "LCA는 무엇을 재는가",
     "body": ["문단1 (250~450자)", "문단2", "문단3"],        // 3~5문단, 총 900~1,600자. 개념 → 왜 필요한가 → 흔한 오해
     "figure": {"type": "flow", "title": "LCA 4단계", "items": ["목표·범위", "LCI", "LCIA", "해석"]},
        // type: "flow"(화살표 순서) | "table"({"head":[...],"rows":[[...]]}) | "list"({"items":[...]}) | "compare"({"a":"...","b":"...","rows":[["항목","A","B"]]}) — 선택
     "example": {"title": "기아 보고서에서는", "body": "실제 보고서·기준서 숫자·문장으로 든 예 (쪽 번호 포함)", "page": 130, "co": "kia"},   // 선택, co: kia|hyundai|none
     "check": [
      {"q": "질문", "options": ["A","B","C"], "ans": 1, "why": "한두 문장"}   // 1~2문항, 방금 읽은 것만 묻는다. 암기 아님.
     ],
     "terms": [{"t": "기능단위", "d": "한 문장 정의", "en": "functional unit"}],   // 0~3개
     "sources": [{"label": "ISO 14044:2006 4.2.3", "url": "https://..."}]   // 이 페이지에서 실제로 연 공식 자료
    }
   ]
  }
 ]
}
```

규칙
- 장마다 4~7페이지. 페이지는 한 화면에서 읽는 분량(900~1,600자). 장 전체로는 신입이 30~50분에 읽을 양.
- 업무 흐름 순서를 지킨다. 개념 나열이 아니라 "이 단계에서 신입이 실제로 하는 일"을 기준으로 페이지를 나눈다.
- 모든 숫자·조항·날짜는 이 세션에서 연 공식 자료(기준서, 제정기관, 감독기관, 법령) 또는 두 보고서 원문(기아 co/kia.txt, 현대차 dl/sr.txt)에서 가져온다. 2차 자료만 있으면 본문에 "(2차 자료 기준)"이라고 쓴다. 확인 못 한 것은 쓰지 않는다.
- 문단 번호는 "문단 29(a)"처럼 쓴다. ¶ 기호 금지. 규칙형/원칙형이라는 말 금지.
- check의 보기는 3개, 하나만 정답. 방금 읽은 페이지 내용으로 풀 수 있어야 한다.
- 게임 용어(클래스·전직·XP·레벨·퀘스트) 금지. 교재는 전문 교육 자료 톤.
