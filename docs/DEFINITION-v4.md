# 원문 독서 기록 · 정의서 v4

작성 2026-10-26 · 작성자 김수현 · 이전: `docs/DEFINITION-v3.md`

---

## 0. 한 문장

**"읽었다"고 말하는 사이트가 아니라, 읽지 않았으면 만들 수 없는 결과물을 보여 주고, 보는 사람이 직접 확인해 보게 하는 사이트.**

## 1. v3에서 바뀐 생각

v3는 읽기 로그, 읽은 시간, 요약으로 증명하려 했다. 그런데 이건 약하다.

| v3의 증거 | 왜 약한가 |
|---|---|
| 읽은 시간, 읽은 쪽 수 | 내가 입력한 숫자다. 부풀려도 아무도 모른다 |
| 요약 | AI가 1분이면 쓴다. 보는 사람이 내가 썼는지 구별할 수 없다 |
| 질문과 답 | 요약보다 낫지만, 이것도 AI가 만들 수 있다 |

증명이 강하려면 세 조건을 갖춰야 한다.

1. **원문을 펴야만 나오는 것**: 요약본이나 AI 답변에는 없고, 원문을 한 줄씩 봐야 보이는 것
2. **틀리면 바로 들키는 것**: 구체적인 쪽, 문단, 숫자로 말해서, 틀렸으면 누구나 확인할 수 있는 것
3. **내가 고칠 수 없는 기록이 남는 것**: 발행처 회신, 커밋 날짜처럼 나 말고 다른 곳이 찍어 준 기록

## 2. 증거의 세 등급

공개 화면은 **A·B 등급이 앞에 오고, C 등급은 뒤에서 받쳐 준다.**

### A등급 · 다른 사람이 확인해 준 것 (가장 강함)

| 증거 | 무엇 | 왜 강한가 |
|---|---|---|
| **발행처 질의와 회신** | 읽다 생긴 의문을 KSSB(회계기준원), 기후에너지환경부, 온실가스종합정보센터에 공식 질의하고 받은 회신 | 질문의 수준이 읽은 깊이를 보여 주고, 회신 날짜는 내가 고칠 수 없다 |
| **오탈자·불일치 제보** | 원문에서 찾은 오류(문단 번호 어긋남, 표와 본문 숫자 차이, 번역 불일치)를 발행처에 알린 기록, 반영 여부 | 끝까지 꼼꼼히 읽은 사람만 찾는다 |
| **커밋 이력** | 모든 기록은 GitHub에 올린다. 날짜를 GitHub가 찍는다 | 몰아서 만든 건지, 몇 주에 걸쳐 쌓인 건지가 그대로 보인다 |

### B등급 · 원문을 대조해야만 나오는 것 (핵심)

| 증거 | 무엇 | 예 |
|---|---|---|
| **원문 대조 교정** | AI 해설 원고를 원문과 맞춰 보고 틀린 곳을 고친 기록. 틀린 문장 → 원문 쪽 → 고친 문장 | "AI 원고는 BC105를 19쪽이라 했지만, 원문은 127쪽" |
| **문서 간 대응표** | 같은 주제를 문서마다 어디서 다루는지 조항 단위로 맞춘 표 | 조직경계: 보고·인증 지침 제○조 ↔ KSSB 제2호 B27 ↔ GHGP 3장 |
| **차이 발견** | 대응표를 만들다 보인 차이. 근거는 두 문서 이상의 쪽 | 가스 6종(지침 제9조) ≠ 7종(KSSB B20·B21) |
| **기업 보고서 적용** | 실제 공시·명세서 숫자를 원문 기준으로 검토한 결과 | 기아 데이터표 Scope 2 697.9천 = 시장기반 (KSSB는 지역기반 필수) |
| **쪽 지도** | 본문 쪽마다 한 줄 메모. 어느 쪽을 골라도 내 메모가 나온다 | "제2호 19쪽: 29⑴㈒는 섞였을 때만. 조건문을 놓치기 쉽다" |
| **손 메모 사진** (선택) | 인쇄본에 밑줄 긋고 적은 메모 사진 | 손글씨는 AI가 대신 못 한다 |

### C등급 · 내가 남긴 기록 (보조)

| 증거 | 쓰임 |
|---|---|
| 요약, 질문, 읽기 로그 | 공부 과정을 보여 주는 보조 자료. 홈의 큰 숫자로 내세우지 않는다 |

## 3. 핵심 장치: "직접 확인해 보세요"

사이트가 스스로 증명하려 하지 않는다. **보는 사람이 시험해 볼 수 있게 한다.**

1. **아무 쪽이나 고르기**: 면접관이 문서와 쪽 번호를 고르면, 그 쪽의 내 메모와 원문 링크가 나온다. 메모가 없는 쪽은 "아직 안 읽음"으로 솔직히 보인다.
2. **원문 바로 펴기**: 모든 주장 옆에 원문 PDF의 해당 쪽으로 바로 가는 링크를 단다(`파일.pdf#page=127`).
3. **면접에서 시험하기 안내**: "이 화면에서 아무 쪽이나 골라 질문해 주세요"를 첫 화면에 쓴다.

## 4. 페르소나

| 누구 | 시간 | 묻는 것 | 첫 화면에서 볼 것 |
|---|---|---|---|
| 채용 담당자 | 30초 | 뭘 읽었고, 그게 진짜인가? | 문서 4종 + A·B등급 숫자 (교정 ○건, 대응 ○쌍, 질의 회신 ○건) |
| 실무 팀장·면접관 | 5분 | 실무에 쓸 수 있나? | 차이 발견, 기업 보고서 적용, 아무 쪽이나 고르기 |
| 작성자 (나) | 매일 | 빨리 남기고 싶다 | 읽기 도구의 메모 칸, 내보내기 |

## 5. 대상 문서 (v3와 같음)

| 순서 | 문서 | 판본 |
|---|---|---|
| 1 | KSSB 지속가능성 공시기준 제1·2호 | 2026.2 의결본 |
| 2 | 배출량 보고·인증 지침 · 배출권거래제 검증지침 | 제2025-64호 · 제2025-165호 |
| 3 | GHG 프로토콜 기업 표준 | 2004 개정판 |
| 4 | 국가 온실가스 인벤토리 보고서 | 2024 (2025.1 공표) |

문서 사이의 연결(대응표, 차이 발견)이 B등급의 중심이다. 그래서 1, 2번을 먼저 끝내고 바로 둘을 잇는다.

## 6. 공개 화면

| 화면 | 담는 것 |
|---|---|
| **홈** | 한 문장, A·B등급 숫자 4개, 문서 4종 진도, 대표 발견 3개, "아무 쪽이나 골라 보세요" |
| **문서** | 판본·원문 링크, **쪽 지도**(쪽마다 메모 있음/없음), 목차별 기록 |
| **대응표** | 주제별로 4개 문서의 조항을 한 줄에. 칸을 누르면 원문 쪽으로 |
| **발견** | 차이 발견 + 기업 보고서 적용. 근거 두 개 이상, 실무에서 확인할 것 |
| **교정 기록** | AI 원고에서 틀린 곳 → 원문 → 고친 내용. 몇 건, 어떤 종류(쪽수·숫자·해석) |
| **질의·제보** | 발행처에 보낸 질문과 회신, 오류 제보와 반영 여부 |
| **기록 방법** | AI를 어디까지 썼는지, 등급별 증거의 뜻, 기록 규칙 |

## 7. 규칙

1. 모든 주장에 원문 위치(문서·판본·쪽·문단)를 단다.
2. AI가 만든 문장은 AI가 만든 것이라고 표시한다. 내가 원문으로 확인한 것만 "확인"으로 바꾼다.
3. 기존 저장소의 `REVIEW-*.md` 교정 기록은 AI가 대조한 것이다. **내가 원문을 펴서 다시 확인한 건만** 교정 기록으로 공개한다.
4. 읽은 시간·쪽 수 같은 자기 입력 숫자는 홈 첫 줄에 두지 않는다.
5. "완독"은 쪽 지도의 본문 쪽이 모두 채워졌을 때만 쓴다.
6. 틀린 기록을 발견하면 지우지 않고 "정정"으로 남긴다. 고친 흔적도 증거다.

## 8. 데이터

| 파일 | 필드 |
|---|---|
| `data/log/pages-<문서>.json` | 문서, 쪽, 한 줄 메모, 날짜 |
| `data/log/fixes.json` | AI 원고 문장, 원문 위치, 고친 문장, 종류, 확인 날짜 |
| `data/log/map.json` | 주제, 문서별 조항·쪽 |
| `data/log/finds.json` | 제목, 내용, 근거 2개 이상, 실무 확인 사항, 종류(차이/기업 적용) |
| `data/log/inquiries.json` | 대상 기관, 보낸 날, 질문, 회신 날, 회신 요지, 상태 |

모두 저장소에 커밋한다. 커밋 날짜가 기록 날짜를 보증한다.

## 9. 완성 기준

**문서 하나**
- 본문 쪽 지도 100%
- 원문 대조 교정 10건 이상
- 다른 문서와 대응표 10줄 이상
- 발견 3개 이상, 그중 기업 보고서 적용 1개 이상

**전체 (지원 전 최소선)**
- KSSB + 배출권거래제 지침 두 문서 완성
- 발행처 질의 1건 이상 보냄 (회신은 기다리는 중이어도 공개)

## 10. 작업 순서

1. 이 정의서 확정
2. 읽기 도구에 "쪽 메모" 칸과 내보내기 붙이기 (가장 먼저 필요)
3. KSSB를 읽으며 쪽 메모 + AI 원고 교정 기록
4. 배출권거래제 지침을 읽으며 KSSB와 대응표 만들기
5. 읽다 생긴 의문 하나를 골라 발행처에 질의
6. 공개 화면 v8 (A·B등급 중심으로 v7 시안 고침)
7. GHG 프로토콜 → 국가 인벤토리 순서로 반복

## 11. 면접에서

- "정말 읽었어요?" → "아무 쪽이나 골라 주세요." 쪽 지도를 연다.
- "그래서 뭘 알게 됐어요?" → 발견 하나. 두 문서 원문을 나란히 연다.
- "AI 썼죠?" → "네. AI 원고를 원문과 맞춰 보며 ○건을 고쳤습니다." 교정 기록을 연다.
- "실무에 쓸 수 있어요?" → 기업 보고서 적용 사례.

## 12. 솔직한 한계

어떤 사이트도 "읽었다"를 100% 증명하지는 못한다. 마지막 증명은 면접에서 내 입으로 설명하는 것이다. 이 사이트의 역할은 그 면접을 **불러오는 것**이다. 구체적인 쪽과 숫자를 걸어서 "이 사람은 물어보면 답할 것 같다"는 확신을 주고, 면접관이 직접 시험할 수 있게 문을 열어 두는 것이다.
