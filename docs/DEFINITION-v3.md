# 원문 독서 기록 · 정의서 v3

작성 2026-10-26 · 작성자 김수현 · 이전 정의서: `docs/DEFINITION.md`(v1.2, 리딩 클래스)

## 0. 한 문장

**기후·온실가스 컨설턴트 지원자 김수현이 기준 문서를 원문으로 읽었다는 것을, 내가 남긴 기록으로 증명하는 포트폴리오.**

## 1. 목적

| | 내용 |
|---|---|
| 증명할 것 | ① 원본을 **읽었다** ② **이해했다**(내 말로 쓸 수 있다) ③ **판단할 수 있다**(문서끼리 비교하고 보고서에 적용한다) |
| 보여 주는 방법 | AI가 쓴 해설이 아니라 **내가 쓴 기록**과 **원문 위치(쪽수)** |
| 하지 않는 것 | 교육 플랫폼, 문제 은행, 회원 기능, 서버, 아직 읽지 않은 문서의 목록 노출 |

## 2. 페르소나

| 누구 | 머무는 시간 | 묻는 것 | 보여 줄 것 |
|---|---|---|---|
| **작성자 (김수현)** | 매일 15~60분 | 빨리 읽고 빨리 남기고 싶다 | 읽기 도구, 기록 입력, 공개용 내보내기 |
| **채용 담당자** | 30초 | 무엇을 읽었나? | 읽은 문서 목록, 판본, 진도, 읽은 기간 |
| **실무 팀장 · 면접관** | 5분 | 정말 읽었나? 읽은 걸로 판단할 수 있나? | 내 요약, 내 질문과 답, 문서 간 발견, 원문 쪽수 |

## 3. 증명 원칙

1. **모든 기록에 원문 위치를 단다.** 문서명, 판본, 쪽수(필요하면 문단·조항 번호). 면접관이 원문을 펴서 확인할 수 있어야 한다.
2. **기록은 내 글이다.** AI 해설을 옮겨 적지 않는다. 원문 인용은 짧게(한두 문장), 나머지는 내 말로 쓴다.
3. **날짜와 시간은 자동으로 남는다.** 읽은 날, 읽은 시간, 기록한 날을 도구가 기록한다. 손으로 고치지 않는다.
4. **AI 사용을 숨기지 않는다.** 읽을 때 AI 해설 원고를 보조로 썼다는 사실과 범위를 "기록 방법" 화면에 밝힌다.
5. **완독한 것만 '완독'이라고 쓴다.** 진도는 목차 항목 단위로 계산하고, 덜 읽은 문서는 "읽는 중"으로 표시한다.

## 4. 증거 4종 (기록의 종류)

| 종류 | 무엇 | 필수 필드 |
|---|---|---|
| **읽기 로그** | 언제, 어디를, 얼마나 읽었나 | 문서, 목차 항목, 날짜, 읽은 시간(분), 원문 쪽 범위 |
| **요약** | 목차 항목 하나를 내 말로 1~3문장 | 문서, 목차 항목, 본문, 원문 쪽 |
| **질문** | 읽다가 생긴 의문과, 원문에서 찾은 답 | 질문, 답(없으면 "미해결"), 답의 원문 쪽 |
| **발견** | 문서끼리 다른 점, 보고서에 적용했을 때 보인 점 | 제목, 내용, 근거 2개 이상(문서·쪽), 실무에서 확인할 것 |

공통 필드: `id`, `doc`, `section`, `created`(자동), `tags`, `public`(공개 여부).

## 6. 화면

**공개용 (방문자)**

| 화면 | 담는 것 |
|---|---|
| 홈 | 한 줄 소개, 지표 4개(읽은 문서 · 읽은 원문 쪽 · 기록 수 · 읽은 시간), 서가, 대표 발견 3개 |
| 문서 | 판본·발행처·원문 링크, 읽기 로그(날짜별), 목차별 기록(요약·질문·발견), 진도 |
| 발견 노트 | 문서를 넘나드는 발견 카드. 근거 문서·쪽, 실무에서 확인할 것 |
| 기록 방법 | 읽은 방식, AI 사용 범위, 원문 파일 위치, 기록 규칙 |

**작성자용 (나만)**: 지금 만든 읽기 화면(v5.1·v6)을 읽기 도구로 쓴다. 기록 입력 칸과 "공개용 내보내기"를 붙인다.

## 7. 데이터 흐름

```
읽기 도구에서 기록 (브라우저 저장)
  → 공개용 내보내기 (public=true만, JSON)
  → 저장소 data/log/<문서>.json 에 커밋
  → 빌드 → 공개 화면
```

서버 없음. 기록 원본은 저장소에 남아 변경 이력(커밋)이 곧 증거가 된다.

## 8. 디자인 규칙

- 글꼴: Pretendard 하나
- 색: 배경·글자 + 초록(주색·링크·진행) · 노랑(내 발견 표시) · 빨강(차이·주의)
- 원칙: 화면마다 정보는 적게, 여백은 넉넉히. 장식보다 원문 위치를 또렷하게.
- 단어표: **문서**(기준서·지침·보고서를 통틀어), **목차 항목**(회차 대신), **기록**(요약·질문·발견·로그), **원문 쪽**

## 9. 완성 기준 (문서 하나가 '완독'이 되는 조건)

- 목차 항목 전부에 읽기 로그가 있다
- 목차 항목 전부에 요약이 1개 이상 있다
- 질문 3개 이상, 그중 답을 찾은 것 2개 이상
- 발견 1개 이상 (다른 문서나 기업 보고서와 연결)
- 모든 기록에 원문 쪽이 있다

## 10. 기존 자산 처리

| 기존 | 앞으로 |
|---|---|
| 리딩 클래스 v5.1 / v6 시안 | 작성자용 읽기 도구로 쓴다 (공개 화면에서는 뺀다) |
| 원본 도감·개정 이력 데이터 | 문서 판본·발행처·원문 링크에 재사용 |
| AI 해설 원고 118회차 | 읽기 보조 자료. 공개 화면에 기록처럼 섞지 않는다 |
| 문단 계보 | 발견 노트의 근거 연결에 재사용 |

## 11. 작업 순서

1. 이 정의서 확정
2. 공개 화면 시안 (예시 기록으로 모양 확인) ← 지금
3. 읽기 도구에 기록 입력·내보내기 붙이기
4. KSSB를 읽으며 실제 기록 쌓기 → KSSB 공개
5. 배출권거래제 지침 → GHG 프로토콜 → 국가 인벤토리 순서로 반복

## 12. 면접에서 쓰는 법

- "어떤 문서를 읽었나요?" → 서가
- "정말 읽었나요?" → 문서 페이지의 읽기 로그와 원문 쪽
- "그래서 무엇을 알게 됐나요?" → 발견 노트 하나를 골라 근거 문서 두 개를 펴서 설명
- "AI를 썼나요?" → 기록 방법 화면: 해설은 보조로 썼고, 기록은 내가 썼다
