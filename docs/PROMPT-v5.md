# 기준 문서
저장소 goalbangg-prog/Climate-Change-Professional-Maker 의 `docs/DEFINITION-v5.md`가 유일한 기준이야.
작업 전에 이 파일을 끝까지 읽어. 정의서와 다른 판단이 필요하면 만들기 전에 먼저 물어봐.
v3·v4 정의서, 리딩 클래스(src/reading.html), proto/ 시안들은 참고만 하고 그 방향을 따라가지 마.

# 한 줄 목적
퇴근 후 집 컴퓨터에서 하루 30분~1시간, KSSB 기준서를 원문(PDF)으로 목차 항목 하나씩 읽고, 내 정리·구조도·상황 문제를 남기는 나만의 읽기 공간.

# 만들 것
새 폴더 `kssb/` 안에 정적 사이트로 만든다. 기존 index.html과 src/는 건드리지 않는다.

```
kssb/
  index.html        첫 화면 + 오늘의 읽기 + 내 기록 (해시 라우팅 #/ #/read/<id> #/notes)
  app.js
  style.css
  data/items.json   목차 23개 항목
  pdf/kssb-1.pdf    내가 넣는다
  pdf/kssb-2.pdf    내가 넣는다
```

## data/items.json
`data/books/kssb-1.json`, `data/books/kssb-2.json`의 sessions에서 id, title, pages(PDF 쪽 [시작, 끝])를 가져와 만든다.
- 항목마다 필드: `id, doc("kssb-1"|"kssb-2"), title, start, end, part, map`
- `map`은 "이 항목이 무엇을 정하는 부분인지" 1~2문장 지도 초안. 기존 sessions의 intro를 참고하되 **해설이나 요약이 아니라 위치 안내**로만 쓴다.
- pages 두 값이 본문 쪽과 부록 쪽처럼 떨어져 있는 항목이 있어(예: k1-3 [9, 43]). start=첫 값으로 쓰고, 두 번째 값은 `also`로 따로 둔다. 숫자를 지어내지 마.
- 순서: k0, k1-1 ~ k1-11 (제1호, 12개), k2-1 ~ k2-11 (제2호, 11개)

## 화면 ① 첫 화면 (#/)
- 가운데 큰 버튼 하나: "이어 읽기 — <다음 항목 이름>". 할 일은 이것 하나.
- 그 아래 KSSB 전체 지도: 23개 항목을 제1호·제2호로 나눠 보여 주고, 읽은 항목은 색이 채워진다. 누르면 그 항목 읽기로 간다.
- 진도 "n / 23", 지금 몇 주차인지(1~2주차 제1호, 3~4주차 제2호 계획 기준).
- 채용 담당자도 보는 화면이라 **예쁘게**. 다만 색은 배경·글자 + 초록(주색) + 노랑(강조) + 빨강(주의) 3색만.
- 사이트가 완성되면 바로 공개한다. 기록이 적어도 "쌓이는 중"으로 자연스럽게 보이게.

## 화면 ② 오늘의 읽기 (#/read/<id>)
단계별로 한 화면씩, "이전 / 다음" 버튼으로 넘어간다. 위에 1-2-3-4 단계 표시.
1. **지도**: 전체 23개 중 이 항목의 위치, map 문장, 원문 쪽 범위
2. **원문**: PDF를 iframe으로 띄우고 `pdf/kssb-1.pdf#page=<start>`로 시작 쪽을 연다. 해설·요약은 넣지 않는다. 아래에 "다 읽었어요" 버튼 → 누르면 이 항목 완료 체크 + 날짜 기록.
3. **내 정리**: 긴 글 칸(제한 없음) + 들여쓰기 구조도 칸. 구조도 칸에 들여쓰기(스페이스 2칸)로 쓰면 옆에 나무 모양 그림이 실시간으로 그려진다. 라이브러리 없이 SVG나 HTML로 직접 그려도 되고, 써야 하면 이유를 먼저 말해.
4. **상황 문제**: 상황 1~2개 칸, 내 답 칸, 근거 문단 칸(예: "제1호 문단 B19, 38쪽"). 상황 문장은 내가 다른 AI에서 받아 붙여 넣는다. 사이트 안에 AI 호출이나 자동 채점은 없다.
- 3·4단계에는 "원문 다시 보기" 버튼: 누르면 화면 오른쪽에 PDF가 열린다(같은 쪽).
- 입력은 자동 저장.

## 화면 ③ 내 기록 (#/notes)
- 항목별로 정리, 구조도, 상황 문제를 모아 본다. 비어 있는 항목도 보인다.
- 처음 지도(map)와 내가 그린 구조도를 나란히 비교.
- 백업: "파일로 내보내기(JSON)" / "파일 불러오기". 불러올 때는 형식을 검사하고, 모르는 항목 id는 버린다. 잘못된 파일이면 기존 기록을 지우지 않는다.

## 저장
- 서버 없음. localStorage 키 하나(`kssb-v5`)에 `{ version, items: { <id>: { done, doneAt, note, tree, cases:[{q,a,ref}] } } }`.
- localStorage 읽기·쓰기는 try/catch로 감싼다.

## 원문 PDF
- 공개 사이트에 그대로 올린다. 모든 PDF 화면 아래에 "출처: 한국회계기준원 지속가능성기준위원회, KSSB 지속가능성 공시기준 2026.2 의결본" + 공식 링크를 표시한다.
  - 제1호: https://www.kasb.or.kr/front/board/View3012.do?siteCd=002000000000000&gubun=3012&accstdSeq=3748&seq=&tab=A&bu=B&searchfield=TITLE&searchword=&categoryList=&searchfield2=ENACTMENT_DT&s_date_start=&s_date_end=
  - 제2호: 위 주소에서 accstdSeq=3749
- PDF가 아직 없으면 "pdf/ 폴더에 파일을 넣어 주세요" 안내와 공식 링크를 보여 준다.
- data/books의 pages가 내가 넣을 PDF의 쪽 번호와 맞는지는 내가 PDF를 넣은 뒤 함께 확인한다. 맞지 않으면 items.json만 고친다.

# 작업 순서 (단계마다 멈추고 나에게 보여 줘)
1. items.json 만들기 → 23개 항목 표로 보여 주기
2. ② 오늘의 읽기 1·2단계 (지도, PDF, 다 읽었어요)
3. ① 첫 화면 (이어 읽기 + 전체 지도)
4. ② 3단계 정리 + 들여쓰기 구조도
5. ② 4단계 상황 문제
6. ③ 내 기록 + 내보내기·불러오기

# 확인 방법 (단계마다)
- Playwright로 1440px, 390px 화면을 찍어서 보여 줘. 콘솔 에러 0개, 가로 스크롤 없음.
- "다 읽었어요" → 새로고침 → 체크가 남아 있는지.
- 구조도: 3단계 들여쓰기가 그림으로 맞게 그려지는지.
